# Сохранение базы при обновлении

Обычный git pull не удаляет игнорируемую bot.db. Если данные пропадают после
кнопки обновления на хостинге, проверьте, не пересоздаётся ли каталог/контейнер.
Код не может сохранить файлы, если платформа удаляет всё хранилище.

Перед первым развёртыванием остановите бота и скачайте bot.db вместе с
bot.db-wal и bot.db-shm, если они присутствуют. Не удаляйте старые файлы.
На BotHost используется постоянное хранилище /app/shared:

```env
BOT_DATA_DIR=/app/shared/hunter-bot
BOT_REQUIRE_EXISTING_DB=1
```

Укажите эти переменные в окружении хостинга или .env.
Если /app/shared существует в Linux, путь /app/shared/hunter-bot выбирается
автоматически даже без BOT_DATA_DIR. Для этого пути по умолчанию запрещено
создавать пустую базу: при отсутствии прежней базы запуск остановится.
Рабочая база: /app/shared/hunter-bot/bot.db.
Бэкапы: /app/shared/hunter-bot/backups/.
Перенос проверяет сначала data/bot.db, затем bot.db в корне проекта.
Если прежний bot.db доступен в корне проекта, бот перенесёт его через SQLite
Backup API в BOT_DATA_DIR/bot.db, не удаляя оригинал и не заменяя существующую базу.
Вне BotHost, если /app/shared отсутствует, используется data/ в проекте: это защищает от обычного Git pull,
но не от очистки каталога платформой.

После успешного переноса установите BOT_REQUIRE_EXISTING_DB=1: при потере
файла бот остановится с ошибкой вместо незаметного создания пустой базы.
Снимки сохраняются в BOT_DATA_DIR/backups при запуске, ежедневно и перед
встроенным автообновлением; для каждого типа остаются последние семь.
Перед обновлением кнопкой сайта нужен отдельный бэкап: код бота не управляет этой кнопкой.
Периодически скачивайте копии за пределы хостинга.

Обновление db/database.py требует полного перезапуска процесса: горячая
перезагрузка cog не применяет миграции модуля базы.
