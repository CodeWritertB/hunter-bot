# Hunter Bot: описание проекта

Документ описывает устройство бота, ответственность Python-модулей, обработку событий, внешние интеграции и локальное хранение данных. Пользовательские шаги запуска и таблицы команд приведены в [README.md](./README.md).

## Назначение

Hunter Bot — бот на `disnake`, который работает на Discord-серверах как набор загружаемых расширений (`cogs`). Главный файл создаёт бота с slash-командами и всеми intents, подключает расширения, настраивает логи и запускает периодическую смену статуса.

Функции включаются независимо: базовым функциям Discord достаточно токена бота; игровые интеграции и музыка требуют собственных API-ключей или серверных адресов. Настройки каналов, ролей и привязок хранятся отдельно для каждой гильдии в SQLite.

## Запуск и общая схема

1. `main.py` загружает переменные из `.env`, настраивает ротацию файловых логов и создаёт `commands.InteractionBot`.
2. При импорте `db/database.py` создаётся или открывается `bot.db`, включается WAL и выполняются создание таблиц и миграция схемы.
3. `main.py` загружает расширения из `cogs/`. Каждое расширение регистрирует slash-команды, обработчики Discord-событий и (где необходимо) фоновые циклы.
4. `on_ready` в отдельных расширениях синхронизирует данные участников, восстанавливает постоянные представления и запускает/подготавливает периодическую работу.
5. Пользовательские действия обрабатываются slash-командами, кнопками, select-компонентами и модальными окнами; внешние данные запрашиваются через Steam, OpenDota, Faceit или Lavalink.

`BOT_TOKEN` обязателен. Остальные переменные описаны в `.env.example`. Интенты `members`, `presences` и `message_content` требуют включения в Discord Developer Portal.

## Точка входа и зависимости

### `main.py`

- Настраивает корневое логирование в консоль и в `logs/`: общий файл с ротацией и отдельный журнал ошибок.
- Загружает `.env` перед импортом расширений, поэтому переменные API доступны при инициализации модулей.
- Создаёт `InteractionBot` с `Intents.all()`.
- Загружает все модули из `cogs/`.
- Периодически выставляет статус бота: число активных голосовых комнат и их слушателей либо текущий музыкальный трек.
- Останавливает запуск понятной ошибкой, если отсутствует `BOT_TOKEN`.

### `requirements.txt`

Фиксирует версии `disnake`, `python-dotenv`, `yt-dlp`, `PyNaCl` и `aiohttp`. Это Discord API-клиент, загрузчик метаданных видео/плейлистов и HTTP-клиент.

### `db/database.py`

Единая SQLite-обёртка. Файл базы находится в корне проекта. При старте модуль создаёт таблицы, добавляет отсутствующие колонки старым базам и использует подготовленные параметры для значений SQL-запросов.

| Таблица | Содержимое |
|---|---|
| `servers` | Настройки каналов, ролей верификации и игровых уведомлений по Discord-серверу |
| `temp_channels` | Идентификаторы временных голосовых комнат и их владельцы |
| `room_settings` | Последние настройки комнаты владельца |
| `panel_messages` | Сообщения панелей комнат для восстановления после перезапуска |
| `xp`, `xp_roles` | XP, уровни и роли за уровень |
| `voice_streaks` | Горячие/холодные стрики и дата последней активности |
| `completed_migrations` | Выполненные одноразовые операции по серверам |
| `members`, `server_stats` | Счётчики сообщений, минут в войсе и пик онлайна |
| `steam_links`, `members.faceit_id` | Steam- и Faceit-привязки пользователей |
| `processed_matches` | Дедупликация уведомлений о матчах Dota 2 |
| `dota_players` | Ранг и недельные результаты игроков Dota 2 |

Функции этого модуля обеспечивают чтение и запись настроек, начисление XP, обновление стриков и статистики, привязку Steam/Faceit, хранение панелей и статистику матчей. При старте старых баз схема мигрируется без удаления пользовательских данных.

## Расширения `cogs/`

| Файл | Ответственность |
|---|---|
| `admin_panel.py` | `/admin`: показывает текущие настройки бота и позволяет задать связанные с его функциями каналы и роли через модальные окна |
| `autoupdate.py` | Раз в 10 минут делает `git fetch`, проверяет `origin/main`, выполняет `git pull --ff-only` и перезагружает зарегистрированные расширения |
| `backup.py` | Раз в сутки копирует SQLite-базу в `backups/` и оставляет семь последних копий |
| `cs2.py` | Привязка Faceit, игровые сводки CS2, периодический поиск и обновление матчей через Faceit Data API |
| `dota.py` | Привязка Steam, статистика OpenDota, поиск матчей через Steam API, live- и итоговые сводки, недельные результаты и обнаружение изменения ранга |
| `help.py` | Эфемерная справка по командам; администраторам отображается дополнительный раздел |
| `info.py` | Сведения об участнике/сервере, очистка сообщений и отправка личного сообщения администратором |
| `logger.py` | События удаления/редактирования сообщений, изменения участников, ролей, каналов, банов и голосовых перемещений; аудит действий отправляется в настроенные каналы |
| `members.py` | Приветствия и уведомления об уходе участника в установленный канал |
| `music.py` | Поиск аудио и управление очередью через Lavalink v4; для Spotify-ссылок код пробует извлечь метаданные через `yt-dlp` |
| `reload.py` | `/reload`: перезагрузка одного расширения или всех расширений без полного перезапуска процесса |
| `streaks.py` | При первом запуске для каждого сервера загружает всех участников, однократно обнуляет прежние горячие/холодные стрики и удаляет старый суффикс стрика из доступных для изменения ников; далее ведёт ежедневные стрики входа в голосовые каналы, сбрасывает их в полночь по московскому времени и обновляет суффикс ника |
| `tracker.py` | Синхронизация участников и подсчёт сообщений, времени в войсе и пикового онлайна |
| `verify.py` | Роль гостя при входе и верификация кнопкой: проверка ника, выдача роли участника и постоянное представление |
| `voice_rooms.py` | Создание временной комнаты при входе в лобби, панель владельца, сохранение настроек, передача прав и удаление пустых комнат |
| `xp.py` | Начисление случайного XP за сообщения с кулдауном, XP за интервалы в голосовом канале, повышение уровня, роли и рейтинги |

### Внутренние потоки событий

- Сообщение от пользователя обновляет счётчик статистики в `tracker.py`; `xp.py` отдельно проверяет cooldown и при необходимости начисляет XP.
- Вход/выход из voice обрабатывается статистикой, стриками, системой XP, музыкальным плеером и журналом событий.
- Новичок получает роль гостя, если настроена верификация. Кнопка открывает модальное окно, затем бот меняет ник и роли.
- Вход в voice-лобби создаёт отдельную комнату и панель. Владелец управляет названием, лимитом, видимостью и доступом. Состояние панелей восстанавливается после рестарта.
- Трекер Dota 2 сохраняет обработанные идентификаторы матчей в SQLite, чтобы не повторять уведомление после перезапуска.

## Внешние системы

### Steam и OpenDota

Steam Web API используется для разрешения профиля, обнаружения матчей и получения профилей. OpenDota предоставляет публичную статистику, героев, последние матчи и детали завершённых игр. Участник должен самостоятельно привязать Steam-профиль командой `/link_steam`.

### Faceit

Faceit Data API используется для поиска профиля и получения CS2-статистики и матчей. Ключ задаётся через `FACEIT_API_KEY`; в исходниках он не хранится. Для привязки используется `/link_cs`.

### Lavalink

Музыкальный плеер соединяется с Lavalink v4 по WebSocket и REST. Адрес, порт, пароль и режим TLS задаются переменными `LAVALINK_*`. Если хост или пароль не указаны, подключение не запускается и музыкальные команды сообщают, что сервис недоступен.

## Логи, файлы и приватность

- `bot.db` содержит идентификаторы пользователей и серверов, имена, настройки, игровые привязки и агрегированную активность. База исключена из Git.
- `backups/` содержит копии той же базы, а `logs/` — технические и серверные события. Обе папки локальные и исключены из Git.
- Включённый журнал Discord может записывать содержимое удалённых и изменённых сообщений, а `/send_message` пишет текст отправленного сообщения в технический лог. Ограничьте доступ к логам и задайте срок их хранения.
- Временные состояния некоторых функций находятся в памяти процесса. Например, отслеживание голосовой сессии начинается заново после перезапуска, поэтому незавершённое время до перезапуска не учитывается.

## Эксплуатационные заметки

- Бот требует разрешений Discord на обработку событий и операций, используемых включёнными функциями. Административные команды защищены разрешениями; панель управления игровым сервером дополнительно проверяет администратора при взаимодействии.
- Автообновление привязано к `origin/main`. Запускайте его только в клоне с доверенным remote и веткой; fast-forward обновление не заменяет локальные незакоммиченные изменения.
- Бэкап хранится рядом с приложением. Для аварийного восстановления и защиты от потери узла используйте дополнительную копию вне сервера.
- Внешние API могут ограничивать частоту запросов, менять формат ответов или быть недоступны; это влияет на соответствующие игровые функции, но не на базовые Discord-команды.
